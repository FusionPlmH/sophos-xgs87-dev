# 10 · 这台机器独特设计的最佳用法

> 🏷 **状态（2026-11-23 复核）**：💡 **设想**：不是实测记录，用之前先看 README 的能力表。

## 10.0 设计本质

XGS 87 不是一个"路由器"，而是**两台独立计算机 + 一块共享的交换芯片**：

```
┌───────────────────────────────┐        ┌───────────────────────────────┐
│ 节点 A：x86 (2C/4G/16G eMMC)  │        │ 节点 B：NPU (4C A72/2G)       │
│ • 通用 Linux，生态全           │  PCIe  │ • 4×1G + SFP，硬件交换         │
│ • 有 USB、SATA 控制器、串口     │◄──────►│ • 10G CPU 链路                │
│ • 没有网口                     │ 串口   │ • 有 crypto 扩展（AES/SHA）   │
└───────────────────────────────┘        └───────────────────────────────┘
```

**能同时利用两者的方案，才算"用对了"。** 只用一个节点，另一个就是浪费。

## 10.1 能力矩阵

| 能力 | x86 | NPU | 结论 |
|---|---|---|---|
| 通用软件/容器/生态 | ★★★★★ | ★★☆ | 应用跑在 x86 |
| 网络转发/交换 | ☆（无网口） | ★★★★★ | 网络跑在 NPU |
| 加密吞吐 | ★★★（AES-NI） | ★★★★（A72 crypto） | 都行，VPN 优先 NPU |
| 内存/存储 | 4 GB / 16 GB | 2 GB / 7.3 GB | x86 更大 |
| 功耗/散热 | 高 | 低 | NPU 适合 7×24 |
| 可折腾性 | ★★★★★ | ★★★（要重刷） | 实验在 x86 |
| 串口/带外 | 有 COM5 | 有 ttyS2 | 互为主备 |

## 10.2 方案一：家用全能路由 + 服务节点（**推荐**）

**分工**

```
        Internet
           │ (SFP 或 LAN1 做 WAN)
    ┌──────┴──────┐
    │  NPU: OpenWrt│  路由、NAT、防火墙、VLAN、WireGuard、QoS
    │  4×1G + SFP  │  DSA: lan1-4 / sfp / wan
    └──────┬──────┘
           │ NTB (ntb0, 630M–1.7G)
    ┌──────┴──────────────┐
    │  x86: Debian        │  Docker: AdGuard/Pi-hole、Home Assistant、
    │  192.168.1.2        │  Prometheus+Grafana、Syncthing、*arr、Uptime Kuma
    └─────────────────────┘
```

- **NPU 只做网络**：CPU0 跑控制面，CPU1-3 留给转发/加密（沿用原厂 `isolcpus` 思路）。
- **x86 只做服务**：不碰转发，避免 2 核被网络吃满。
- x86 通过 `ntb0` 挂在 LAN 里，LUCI/SSH 从任意 LAN 口可达。

**为什么这样分**：x86 没有网口，硬要它转发就得走 NTB（实测 0.6–1.7 Gbps），
而 NPU 有硬件交换 + 10G 上联，转发几乎不花 CPU。**把转发留在 NPU 是唯一不吃亏的做法。**

**瓶颈**：x86 访问外网走 NTB，最高 ~1.7 Gbps（实测值），家用足够。
**前置工作**：OpenWrt + DSA + NTB（见 09）。

## 10.3 方案二：纯路由器（低功耗 7×24）

只刷 NPU，x86 装个最小 Debian 或者干脆闲置/断电（x86 断电不影响 NPU 启动）。

- 4×1G + SFP，实测空闲 ~10-15 W。
- 适合当主路由/旁路由/实验室出口。
- 浪费了 x86 的 4 GB 内存和算力，但最简单、最稳。

**变体**：x86 上跑一个"网络守护"进程（见方案四），平时休眠。

## 10.4 方案三：x86 为主机，NPU 当"交换机 + BMC"

如果主要需求是**跑服务**而不是路由：

```
        Internet
           │
    ┌──────┴───────┐
    │ NPU: 纯交换   │  U-Boot 配好端口，Linux 只跑 ser2net/monitor
    │ + 带外管理    │  串口代理、看门狗、远程重启
    └──────┬───────┘
           │ 一个面板口接 USB 网卡 → x86（1G 直连，不占 NTB）
    ┌──────┴───────┐
    │ x86: 主服务器 │  Docker/KVM/Home Assistant/NAS
    └──────────────┘
```

**关键技巧**：给 x86 插一个 **USB 千兆网卡**，接到面板口 4。
这样 x86 就有了**独立的 1G 链路**（不用 NTB，不占 NPU 的 CPU），
NPU 退化成"带管理的交换机 + 串口服务器"。

- 成本：一个 USB 网卡（几十块）。
- 收益：x86 的网络性能从 0.6–1.7 Gbps（NTB，耗 NPU CPU）变成 1 Gbps 直连（走交换芯片，零 CPU）。
- NPU 还能同时提供：串口代理（`ser2net`）、上电监控、交换机端口镜像。

## 10.5 方案四：网络实验平台 / IDS 靶场

- NPU 跑 OpenWrt，用 DSA 把 4 个口做成 4 个独立 VLAN/网桥。
- 端口镜像：把 WAN 口镜像到 lan4，接一台机器跑 Suricata/Zeek。
- x86 跑流量生成（`iperf3`、`tcpreplay`）和日志分析。
- 优点：真实硬件交换，不是 veth，实验更接近生产。
- 需要：DSA 的 mirror 支持（`tc mirred` 或 `mv88e6xxx` 的 port mirror）。

## 10.6 方案五：NAS / 媒体中心（受限于存储）

- x86 前面板 USB 是 **EHCI 2.0**（~40 MB/s），接 USB SSD 只能到 35–40 MB/s。
- 16 GB eMMC 做系统盘，媒体库放 USB 硬盘。
- 2 核跑 Jellyfin 软解勉强（1080p 可以，4K 不行，无 GPU）。
- 价值一般，适合"顺便"而不是主用途。

## 10.7 共用基建（无论哪个方案都要做）

| 基建 | 作用 | 工作量 |
|---|---|---|
| **NTB 链路** | x86 ↔ NPU 的 1Gbps 级虚拟网口 | 中（要改内核+DT） |
| **DSA 交换机** | 4 口 + SFP 变成标准 Linux 网口 | 中（要试 mv88e6xxx） |
| **串口代理** | x86 上 `ser2net` 暴露 NPU console | 小 |
| **NPU 监管服务** | 抓 boot log、自动进 U-Boot、重启 | 小-中 |
| **MCP2210 工具** | 从 x86 备份/恢复 SPI NOR | 中 |
| **A/B 启动** | p1/p2 双系统 + 失败回滚 | 小（U-Boot env 现成） |
| **LED 映射** | PCA9555 驱动每个口的灯 | 小 |
| **SFP 支持** | i2c EEPROM + gpio | 小 |

## 10.8 硬件增强（低成本高回报）

| 增强 | 效果 | 备注 |
|---|---|---|
| **USB 千兆网卡**（x86） | x86 获得 1G 直连，绕过 NTB | 方案三的核心 |
| **USB SSD**（x86） | 存储从 16 GB → TB 级 | USB2.0 限速 ~40 MB/s |
| **Wi-Fi 卡**（M.2/mini-PCIe） | 变成 AP | 参考机型有 QCA988x；本机需确认插槽 |
| **SFP 模块** | 光纤/10G 上联 | 先确认 port9 速率能力 |

## 10.9 功耗与寿命

- 两颗 SoC 都是嵌入式低功耗型号，空闲估计 **10–20 W**。机箱有风扇，但不是软件能调的（见 19）。
- eMMC 写入寿命有限：日志/容器数据尽量放 tmpfs 或外部存储，开 `noatime`。
- NPU 的 RTC 没有电池时回 2105 年，日志时间不可信，建议 NTP 强制同步。

## 10.10 一句话总结

> **让 NPU 干它擅长的事（交换/转发/加密），让 x86 干它擅长的事（通用计算/容器），
> 中间用 PCIe NTB 连起来；如果不想折腾 NTB，就给 x86 插个 USB 网卡接面板口。**

方案一（OpenWrt@NPU + 服务@x86）是"最正统"的复活方式；
方案三（USB 网卡 + NPU 当交换机/BMC）是"最快见效"的方式。
建议**先做方案三拿到可用系统，再逐步过渡到方案一**（见 [11-roadmap.md](11-roadmap.md)）。
