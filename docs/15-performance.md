# 15 — 性能标定与可采纳项

> 🏷 **状态（2026-11-23 复核）**：✅ **实测数据**；结论已并入 16（EIP197）与 18（同族对比）。

> 本文回答三个问题：**这台机器的真实性能上限在哪**、**小包/大包与硬件加密各是什么量级**、
> **厂家的 BSP 与固件 dump 里到底有什么可以采纳**。全部数字来自实机测量。

## 15.1 CPU 主频：实测 **1.6 GHz**，没有可挖余量

在没有 cpufreq 驱动的情况下用一个依赖链基准直接测主频（A72 的 `ADD` 是 1 周期）：

```c
/* 32 条相互依赖的 add x0,x0,#1，消除循环开销 */
总加法数 / 耗时 = 主频
```

```
1,600,000,000 次依赖 ADD  →  1.001 s  →  1598 MHz
  640,000,000 次依赖 ADD  →  0.400 s  →  1598 MHz
```

**结论：CPU 跑在 1.6 GHz。** CN9130 (AP807) 的器件上限约 2.0 GHz，但：

- 主线的 `armada-8k-cpufreq` 是**读当前频率再按 1/2/3/4 分频**，只能降不能升；
- 原厂 config 用的是 `CPU_FREQ_DEFAULT_GOV_USERSPACE` + 固定频率，**原厂也没超频**；
- 我们的 DT 里没有 `clock-cpu` 的 OPP（原厂 DTB 也没有）。

→ 频率这条没有安全可用的提升空间，放弃。

> 排查过程中先看到 `f06f4000-ap-dclk = 1.2 GHz`，那是 AP 的 DCLK，**不是 CPU 核频**，
> 曾被误认为主频，实测后纠正。

## 15.2 小包 vs 大包：瓶颈是「每包成本」，不是带宽

| 包长 | 实测吞吐 | 折算 PPS | 说明 |
|---|---|---|---|
| 1500 B（TCP 4 流，无 NAT） | **4.74 – 4.81 Gbps** | ≈ 400 kpps | 软件转发的有效上界 |
| 1500 B（同上 + NAT/conntrack） | **3.48 – 3.81 Gbps** | ≈ 300 kpps | NAT 增加约 30% 成本 |
| 64 B（ICMP flood 端到端） | 34 kpps | 34 kpps | 受 `ping` 自身收发限制，非天花板 |
| 64 B（UDP 4 流，iperf3） | 109 kpps | 109 kpps | 受 iperf3 发送端限制 |

按「每包成本恒定」推算：转发能力约 **400 kpps**，即 64 字节小包约 **205 Mbps**，
1500 字节大包约 **4.8 Gbps**。这与 A72 上每包约 1000 周期的软件转发成本吻合。

> 测量口径：netns + veth，关闭 GSO/GRO/TSO，避免聚合放大。veth 没有网卡 DMA/中断开销，
> 所以这些是**软件路径上界**；真实链路还要叠加 mvpp2 收发与交换机转发（后者是硬件线速）。

## 15.3 硬件加密：实测证明**不需要**

| 指标 | 数值 | 换算 |
|---|---|---|
| AES-256-GCM 单核 16 KB | 1,060,716 KB/s | **8.5 Gbps** |
| AES-128-GCM 单核 16 KB | 1,246,391 KB/s | **10.0 Gbps** |
| AES-256-GCM 单核 16 B | 17,483 KB/s | **≈ 1.09 M 次/秒** |

对比转发能力（400 kpps）：

- 大包场景：加密 8.5 Gbps ≫ 转发 4.8 Gbps
- **小包场景**：加密 1.09 M ops/s ≫ 转发 400 kpps

**任何包长下加密都不是瓶颈**，EIP197 硬件卸载（受困于 IFPP 微码在 CN9130 上起不来）
即使修好也不会带来收益。原厂同样不用内核 safexcel，而是走 MUSDK SAM 用户态。

## 15.5 已落地 / 未落地的优化

| 优化 | 状态 | 效果 |
|---|---|---|
| 每口独立 MAC | ✅ 已部署 | 厂商规则，避免多口同 MAC |
| 端口开机自动 up | ✅ 已部署 | 插线即按最高速率协商（1000/Full） |
| `nf_conntrack_max` 65,536 → 524,288 | ✅ 已部署 | 支撑大连接表 |
| `netdev_backlog/budget`、neigh 表、TCP 稳健性 | ✅ 已部署 | 见 `/etc/sysctl.d/90-xgs-router.conf` |
| 中断亲和 | ✅ 天生最优 | mvpp2 IRQ 38–41 已 1:1 绑 CPU0–3，无需 RPS |
| flowtable 软件快路径 | ⏸ 未启用 | veth 上测不出收益（3.80 → 3.48），真实网卡+多规则场景才有效 |
| CPU 隔离 / 提频 | ❌ 放弃 | 隔离 -65% 吞吐；频率无安全余量 |
| mvpp2 ring 1024→2048 | ⬜ 可选 | 小收益，未做 |

## 15.6 结论

这台机器的性能画像已经很清楚：

- **L2 交换**：88E6193X 硬件线速，4×1G + 10G SFP 同时无压力，CPU 不参与（本机面板是 4×1G，不是 8×）
- **L3 转发/NAT**：软件路径 3.5–4.8 Gbps（1.6 GHz × 4 核），与 Sophos 标称的 3,700 Mbps 同级或更高
- **加密/IPsec**：软件 8.5 Gbps 单核，永远不是瓶颈
- **提升空间**：软件调优已到边；再往上只能换**用户态数据面**（VPP/MUSDK），
  但那会绕开交换机、把全部流量挤到单个 10G CPU 口，对本机架构不划算
