# docs/ — 从这里开始

> 这台机器（Sophos XGS 87）被改造成**两台都跑 Debian 13 的电脑**：x86 做通用计算，NPU
> 做网络数据面，两者之间只有一条 PCIe 链路（vNTB）和一条内部串口。
> 全部结论来自实机测量，**每份文档开头都有状态行**：✅ 实测通过 ｜ ⚠️ 有条件/待复现 ｜ ❌ 不可用 ｜ 📦 历史档案。

## 五分钟上手

不知道从哪读，就按这个顺序：

1. **[01 硬件](01-hardware.md)** — 盒子里到底是什么（2 颗 SoC、16 GB + 4 MB 存储、面板 4+1 口）。
2. **[02 架构](02-architecture.md)** — 为什么是两颗芯片、它们怎么连（PCIe 端点 / vNTB / 串口）。
3. **[08 网络](08-network.md)** — x86 没有网口，靠哪条 VLAN 借 NPU 的面板口上网。
4. **[11 运维手册](11-operations.md) §11.0** — 我要重启/复位/换盘时，三十秒版本在哪。
5. **[16 待办](16-remaining-work.md)** — 现在还剩什么没做（这是**唯一**的待办清单）。

## 现状一页纸（2026-11-25 复核）

| | x86 | NPU |
|---|---|---|
| 系统 | Debian 13.8 / 6.12.117（`lean` 镜像，内核被 hold） | Debian 13.8 / 6.12.117（同上） |
| 角色 | 通用计算，**自己没有网口** | 网络数据面（8 口交换机 + 10G MAC） |
| 地址 | `eth0.200` = `10.234.56.2/24`；`eth0.100` = 上游 DHCP（现在无租约） | `br-lan` = `10.234.56.1/24`；`br-wan` = 上游 DHCP（现在是 IPv4LL `169.254.38.2`） |
| 控制台 | 面板 RJ45/micro-USB = `ttyS0`，115200 | x86 的 `/dev/ttyS2`，115200 |
| 登录 | `admin` / `P@ssw0rd`（root 锁定，走 sudo） | 同上 |

**现在唯一的环境问题**：面板 `2/WAN` 没插上游 → 两台都没有默认路由、没有 NTP。
插上就恢复，不用改任何配置。

## 约定

- **文件名 = 章节号**：`09-vntb.md` 里的标题就是 `## 9.x`，所以 `§9.3.5` 能直接定位。
- 引用写法：同目录用 `[09](09-vntb.md)`，从仓库根写 `[09](docs/09-vntb.md)`，章节写 `§9.3.5`。
- 谁改了什么、为什么，看 `git log`；**状态行**是唯一该信的新旧标记。
- 改完文档跑一次 `python3 tools/check-docs.py`：章节引用和相对链接都必须能解析，否则它会报错。
